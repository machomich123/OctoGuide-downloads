# OctoGuide 0.6.5

Find step now requests earlier history through the installed pfQuest server bridge when the native history API is absent. Capture the direct TWQUEST IDs separately from pfQuest's manually marked and inferred pre/close records. Only direct reply IDs enter confirmed character progress. Wait for the pfQuest response window; a timeout, corrupt payload or unsupported query preserves previous facts. Saved snapshots remain character-specific. No full scan or new network request runs at login.

Pickup checks combine the current quest log, confirmed completions, installed quest/start records, level, race, class, profession and faction. Record actual NPC offerings before auto-accept changes the dialog. An observed offer overrides an uncertain database predecessor; missing or expired observations never prove permanent absence. Unknown records, unresolved predecessors and known locks stop the pickup arrow with an explanation, without completing/skipping the quest. Missing pfQuest markers caused by display preferences are separate from eligibility. pfQuest's 886 predecessor for 870 is handled as uncertainty, not an automatic mandatory detour.

Quest-giver positions update from loaded identity-checked NPCs using UnitPosition and map conversion, with a short cache and explicitly labelled database fallback after unloading. Shared pickup circuits retain their fixed NPC identity while allowing that NPC's observed position to move. Remote positions/offers are not live observations; this is not a global server quest-status query.

Use `/octoguide sync` (Find step) for history and route reconciliation. `/octoguide quests` summarizes the current area, or `/octoguide quests 17` for the Barrens. The area snapshot includes every installed NPC/object-start record in that zone, distinguishes active/completed/expected/offered/blocked/unknown, and separately records pfQuest marker-filter visibility. The chat shows totals and up to eight expected/observed names; it does not add every quest to the authored route.

Validation uses Lua 5.0.3 client mocks, the actual installed pfQuest QuestFilter and 241 base Barrens records. Tests cover direct-vs-inferred/manual history, query timeout/corruption, quest-log updates, pre-selection observation order, offer expiry/invalidation, suppressed arrows without fake progress, and observed NPC motion/unloading/identity mismatch. Full-manifest startup must retain the no-full-scan behavior. Native behavior for this release is not yet tested; the active game was not controlled or reloaded.

Update the existing GitHub addon through the launcher and /reload safely outside combat. No new DLL or full game restart is required. The previously discussed automatic downloader/update button is not part of this release.
